<callout emoji="💡"><p><b>核心层级</b>：Stage → Story → Skill + Factor → 测试用例<cite doc-id="WEMab2WMyaeVUfsTQJlc7WrFn2d" file-type="bitable" table-id="tblO3J5Kr6jUxlVE" title="模型评测体系" type="doc" view-id="vewIzuDMqU"></cite></p><ul><li><b>Stage</b>（场域）：评测的大类方向，如"预训练Benchmark"、"端到端操作评测"</li><li><b>Story</b>（测试任务）：一个独立的测试场景，分为<b>能力专项</b>和<b>场景专项</b>两类</li><li><b>Skill</b>（原子能力）：不可再分的单一机器人能力，如抓取、放置、物品识别</li><li><b>Factor</b>（影响因子）：影响某个 Skill 表现的可测量参数，如夹持宽度、表面材质</li><li><b>测试用例</b>：具体的执行 Prompt + 环境配置（factor取值），是最小可执行单元</li></ul></callout>

# 一、整体层级结构

每一层都有明确的职责划分：Stage 决定评测方向，Story 决定测试策略，Skill 是被测对象，Factor 是测试变量，测试用例是执行载体。

| 层级 | 职责 | 示例 | 备注 |
|-|-|-|-|
| Stage | 划定评测大类 | 端到端操作评测 | 可有多个Stage并行 |
| Story | 定义测试策略和场景 | [专项] 抓取基准测试 / 整理桌面 | 能力专项或场景专项 |
| Skill | 标识被测的原子能力 | 抓取、放置、物品识别 | 能力专项一个Story对应一个核心Skill |
| Factor | 描述影响Skill的参数 | 夹持宽度、干扰物、指令表达方式 | 能力专项中是变量；场景专项中是配置 |
| 测试用例 | 具体执行单元 | pick up the red candy（白色桌面，仅有红色糖果） | 每条用例绑定一组Factor取值 |

# 二、Story 的两种类型

Story 根据测试目的分为两类，设计思路和数据用途存在差异。

## 2.1 能力专项 Story

<callout emoji="🔬">
**目的**：在其他变量统一条件下，系统性地测试某个 Skill 在各关键单一变量（single factor）的不同取值下的表现，找到能力边界。
</callout>

<callout emoji="✅">
**适用场景**：定向能力评估、版本间对比、找单点瓶颈
**数据价值**：回答"是哪个 Factor 的哪个取值失败率更高"，结论可溯源
</callout>

**设计方法**：控制变量法——每次只改变一个Factor的取值，其他 Factor 保持默认值不变。

**命名规则**：用 `[专项]` 前缀，如 `[专项] 抓取基准测试`、`[专项] 物品识别基准测试`

**示例**：[专项] 抓取基准测试，测试变量 = 夹持宽度

| 用例ID | Prompt | Skill | 被测Factor | 取值 | 其他Factor |
|-|-|-|-|-|-|
| T1 | pick up the red candy | 抓取 | 夹持宽度 | 小 | 默认值 |
| T2 | pick up the blue bowl | 抓取 | 夹持宽度 | 适中 | 默认值 |
| T3 | pick up the watering can | 抓取 | 夹持宽度 | 大 | 默认值 |

## 2.2 场景专项 Story

<callout emoji="🎬">
**目的**：还原真实使用场景，验证多个 Skill 协同执行时的端到端完成率，同时通过变体设计积累不同条件下的场景表现数据。
</callout>

**设计方法**：按真实任务流程设计完整动作序列，每步可设计多个变体，变体间通过 Key Factor 取值区分；每个变体标注所涉及的 Skill 及其 Factor preset，执行时从该步的变体池中随机抽取一个，同序号变体互斥。通过前置序号标识依赖关系，留空表示该步可独立执行，填入序号表示执行前需确认对应步骤已完成（1,2 = 须全部完成，1|2 = 任一完成即可）。

**示例**：整理桌面场景

<callout emoji="✅">
**执行规则**：每步从该步的变体池随机抽取一个变体ID（如步骤1从1-A/1-B中选），选中后该变体ID下的所有Skill行一起执行。
**数据价值**：
- **场景多样性**：每次执行组合不完全相同，更贴近真实使用
- **变量分析**：长期积累可看"对象表达=功能替代词"时场景完成率是否明显低于"标准名词"
- **根因定位**：场景失败 → 定位到具体步骤 → 下钻到Skill × Factor
</callout>

<callout emoji="💡">
**与能力专项的区别**：
- **能力专项**：穷尽测试，每个Factor取值独立成一条用例，单Skill聚焦，结论精确
- **场景专项**：变体随机组合，不穷尽，多Skill协同，关注端到端完成率和趋势
</callout>

## 2.3 两种类型对比

| 维度 | 能力专项 | 场景专项 |
|-|-|-|
| 测试目的 | 找单个Skill的能力边界和瓶颈 | 验证多Skill协同的端到端完成率 + 场景多样性 |
| Skill数量 | 通常聚焦1个核心Skill | 每步可标注多个Skill |
| Factor角色 | 被测变量，穷尽每个取值 | Key Factor有变体，其他是preset；变体随机组合不穷尽 |
| 变体设计 | 每个Factor取值独立成一条用例 | 每步有多个变体，执行时随机抽取（同序号互斥） |
| 命名规则 | [专项] 前缀 | 场景名称，如"整理桌面" |
| 输出结论 | Skill在各Factor取值下的通过率（精确） | 场景完成率 + 各步骤×Skill通过率 + Factor维度趋势 |
| 适用时机 | 能力定向评估、回归对比、精确归因 | Demo验收、发布评估、真实场景鲁棒性验证 |

# 三、Factor 体系

Factor 挂在 Skill 下，是影响该 Skill 表现的可测量参数。每个 Skill 有若干关键 Factor，能力专项 Story 的设计就是围绕这些 Factor 展开的。当前共定义 24 个 Factor，分为四大类：

| 分类 | Factor 列表 | 取值范围示例 |
|-|-|-|
| 被操作物品属性 | 物体形状、夹持宽度、物体尺寸、物体材质、颜色、摩擦力、物体重量、物理属性、运动状态 | 球型/方块/棍形；小/适中/大；静止/运动中 |
| 环境条件 | 摆放密度、干扰物、背景复杂度、光照条件、背景反射度、遮挡程度 | 稀疏/中等/密集；无/部分/严重遮挡 |
| 指令语言 | 动作表达、对象表达、终态表达、指定本体、序数理解、方位理解、相对位置、语义分类 | 标准动词/同义替换/结果导向；第一个/最左边 |
| 任务结构 | 对象数量、目标位置、目标高度、对齐精度 | 单一/固定多个/不定数量；精确对齐/大致放置 |

<callout emoji="💡">
**每个 Factor 取值可标注 ID / OOD 标签**
- **ID**（In-Distribution）：训练分布内的常见条件，用于统计基线成功率
- **OOD**（Out-of-Distribution）：分布外的泛化测试条件，用于统计泛化成功率
**Factor 在两类 Story 中的角色不同**
- **能力专项**：Factor 是**被测变量**——每次只改变一个 Factor，每个取值对应一条独立的测试用例
- 场景专项：F~~actor 是~~**~~场景配置~~**~~（preset）——描述这个场景的环境设定，是固定的背景条件，不逐一穷举~~
</callout>

# 四、数据分析与泛化评估

## 4.1 数据分析维度

两类 Story 的数据互相补充，分别回答不同层面的问题：

| 分析目标 | 数据来源 | 能回答的问题 |
|-|-|-|
| 能力瓶颈定位 | 能力专项 | 抓取Skill在"夹持宽度=大"时通过率为何只有40%？ |
| 泛化能力评估 | 能力专项（跨所有Factor汇总） | 这个Skill在各种条件变化下整体有多鲁棒？ |
| 场景完成率 | 场景专项 | 整理桌面场景端到端成功率是多少？ |
| 根因回溯 | 两类结合 | 场景失败 → 回查是哪个Skill的哪个Factor出了问题 |

## 4.2 泛化能力的统计方式

泛化能力不设计单独的 Story 类型，而是通过聚合Skill测试内容观察**某个 Skill 跨所有 Factor 取值的整体表现**，反映该 Skill 在条件变化下有多鲁棒。

**第一层：Skill 维度汇总**——为每个 Factor 取值打上 ID / OOD 标签；过滤所有 ID 标签的测试用例计算基线成功率，过滤 OOD 标签的测试用例计算泛化成功率，两者分别统计每个 Skill 跨所有 Factor 取值的综合成功率

| Skill | 总用例数 | 通过数 | 基线得分（ID） | 泛化得分（OOD） |
|-|-|-|-|-|
| 抓取 | 27 | 18 | — | 67% |
| 放置 | 15 | 12 | — | 80% |
| 物品识别 | 12 | 6 | — | 50% |

**第二层：Skill × Factor 下钻**——找出拖累泛化得分的具体 Factor 取值

| Skill | Factor | 取值 | 通过率 |
|-|-|-|-|
| 抓取 | 夹持宽度 | 小 | 90% |
| 抓取 | 夹持宽度 | 适中 | 85% |
| 抓取 | 夹持宽度 | 大 | 40% ↓ 瓶颈 |

<callout emoji="💡">
**两个视角来自同一份数据，不需要额外设计任何 Story**
- **基线得分（ID）** = 仅统计 ID 标签取值的通过率，反映 Skill 在分布内的稳定表现**泛化得分（OOD）** = 仅统计 OOD 标签取值的通过率，衡量 Skill 在条件变化下的鲁棒性
- **能力专项分析** = Skill × Factor 纵向打穿，定位具体瓶颈
- 分析路径：泛化得分低 → 下钻 Skill × Factor → 找到具体短板 → 定向优化
</callout>

<callout emoji="🔁">
**设计闭环**：能力专项定位瓶颈 → 优化后回测同一组用例验证提升 → 场景专项验证整体效果是否同步改善
</callout>
