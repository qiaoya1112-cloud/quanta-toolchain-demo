# Quanta：面向领域用户的一站式模型迭代

## 1. 背景与目标

模型微调通常被视为算法和工程团队的专业工作。领域用户了解机器人应当完成什么任务、在哪些场景下工作，以及什么结果可以被视为成功，但传统流程往往需要在数据采集设备、存储系统、标注工具、训练脚本和评测工具之间反复交接。数据和模型版本分散在不同系统中，评测结果也难以直接说明下一轮应该补充什么数据。

Quanta 将业务目标、数据生产、数据集构建、模型训练、模型下发和效果评测组织为一条连续的工作流。领域用户从业务问题出发，按照平台提供的采集模板、处理流程和训练配置推进模型迭代；算法和工程团队维护训练配方、默认参数与基础设施；平台负责记录过程状态、版本关系和结果证据。其核心价值是降低重复性的工程操作，同时保留领域用户对任务、数据标准和模型效果的判断。

本次流程以标准场景为对象进行验证，结果如下：

| 指标 | 结果 |
|---|---:|
| 标准场景下任务成功率 | **81.2%** |
| 动作完成率 | **93.8%** |
| 端到端迭代周期 | **1 周** |
| 用户体验评分 | **4.32 / 5 分** |

其中，任务成功率反映机器人是否完成目标任务，动作完成率反映任务内部动作或步骤的完成情况；两项指标同时报告，可以区分“动作基本完成但整体任务仍未成功”的情况。端到端迭代周期从目标与方案确认开始，至训练、评测和本轮结论完成结束。用户体验评分用于反映领域用户对流程清晰度、操作易用性、信息完整性和结果可追溯性的综合评价。

## 2. 端到端模型迭代流程

![Quanta 模型迭代闭环与版本血缘](/Users/joanna/Desktop/具身/具身智能-项目/模型平台/outputs/model-iteration/quanta-iteration-optimized.png)

Quanta 将一次模型迭代拆分为六个连续阶段：明确迭代目标与方案、采集并处理数据、构建训练数据集、执行训练并保存模型、合并模型并下发、评测模型并定位问题。六个阶段形成主流程，评测结果通过业务改进回路和模型纠正回路进入下一轮，数据集、训练任务、Checkpoint、部署记录和评测结果则通过版本血缘保持关联。

## 3. 六个阶段的平台能力

### 3.1 明确迭代目标与方案：从业务问题生成可执行的微调方案

迭代从业务目标开始，而不是从训练脚本或计算资源开始。领域用户需要明确任务、场景和目标技能，说明机器人在哪些工作条件下需要改善，并选定当前使用的基线模型或 Checkpoint。平台将业务描述转化为数据需求、训练方案和验收口径，同时固定成功定义、目标场景与评测集。

这一阶段解决了传统流程中“目标由业务提出、方案由算法另行解释”的断点。迭代编号、基线 Checkpoint 和评测集版本会随着方案一起记录，使后续结果能够回答：本轮要改善什么、以哪个模型为基线、用什么标准判断是否达标。

### 3.2 采集并处理数据：用可复用流程生产合格训练数据

平台通过指令包、采集方案和任务分配组织数据采集，保存任务、设备、场景、对象和采集规则等上下文。采集结果进入配置好的数据处理流程，依次完成质检、动作或语义标注、复核、验收和返工。问题数据可以返回上一处理环节或重新采集，避免未经确认的数据直接进入训练集合。

Quanta 还支持针对模型执行偏差的 DAgger 纠正采集。用户指定需要改进的 Checkpoint，在目标设备上执行任务；当模型暴露出抓取、回退、轨迹或动作衔接问题时，由人工接管并记录纠正过程。平台保留来源模型、设备和失败类型，纠正数据经过质检、标注与验收后再进入数据集构建。这使“模型失败”能够转化为具有来源和上下文的训练数据，而不是孤立的人工示教样本。

### 3.3 构建训练数据集：以业务条件组配数据，以版本快照固定训练输入

数据集构建从业务条件出发。用户可以按任务、场景、标签、质量结果和评测反馈筛选数据，通过样本查看、数量统计、分布检查和轨迹查看确认数据是否覆盖目标问题，并识别异常样本、重复样本以及与既有数据集的重叠。

在此基础上，平台支持将常规示教数据与 DAgger 纠正数据按本轮方案进行组配，隔离评测留出数据，并将筛选条件、样本标识、标注版本、处理版本、数据快照和导出格式保存为数据集版本。数据集版本为训练任务提供稳定输入，也为不同迭代之间的差异比较提供依据。团队不需要手工管理底层存储或处理脚本，即可复用数据集、比较版本，并确认某次训练具体使用了哪些数据。

### 3.4 执行训练并保存模型：在受控配置下完成可追溯微调

训练工作区以经过验证的训练模板和推荐配置作为起点。用户选择基础模型或上一轮 Checkpoint、数据集版本、任务类型、推荐参数和运行资源；高级用户可以在受支持的范围内调整学习率、训练轮数或批大小等参数。训练启动前，平台检查数据可用性、模型与训练配方的兼容性、必要设置、资源需求和输出命名，尽量在消耗计算资源前暴露配置问题。

任务启动后，平台统一管理运行环境、资源调度、日志、进度、训练指标和周期性 Checkpoint。每个 Checkpoint 与训练任务、输入数据集、起点模型和训练参数关联，候选模型可以直接进入后续合并、下发和评测。受控配置降低了领域用户的操作门槛，同时保留算法团队对训练配方和默认参数的质量控制。

### 3.5 合并模型并下发：确保评测使用的模型与环境一致

训练得到的候选 Checkpoint 需要经过模型格式所需的合并与压缩处理，再与配套推理软件一起下发到目标设备。平台将模型版本、部署记录、目标设备和推理环境关联起来，形成从训练产物到真机执行的连续记录。

这一环节的重点不是增加操作步骤，而是避免“训练完成的模型”和“实际评测使用的模型”之间出现版本偏差。出现效果变化时，团队可以核对模型版本、部署记录和推理环境，区分问题来自数据、训练配置、模型产物还是设备运行条件。

### 3.6 评测模型并定位问题：用多层证据驱动下一轮改进

平台根据迭代开始时确定的评测集和评分标准组织仿真或真机评测。结果从三个层级呈现：总体指标用于判断模型是否整体改善，分组结果用于观察不同任务、场景或对象的差异，单案例结果则提供视频、轨迹、执行过程、失败原因和关联数据。

标准场景下，本次验证取得 **81.2% 的任务成功率**和 **93.8% 的动作完成率**。两项结果结合起来，说明模型在动作执行层面具备较高完成度，但仍有一部分端到端任务未能转化为最终成功；这些差异可以通过 Badcase 分析进一步定位，而不必只依据一个总成功率做判断。

达到准出标准的候选模型连同评测结果和适用范围留存。未达标的问题则进入下一轮任务：如果某类场景或对象覆盖不足，安排定向补采；如果问题来自模型执行偏差，指定来源 Checkpoint 开展 DAgger 纠正采集；如果问题集中在动作阶段或语义描述，修正标注；如果新增数据带来原有能力退步，检查数据配比、训练配置和评测口径。评测报告因此成为下一轮数据生产的入口。

## 4. 双闭环与全流程血缘

### 4.1 业务改进闭环

评测结果不会停留在报告中。用户从 Badcase 中确认问题场景和失败类型，形成定向补采、标注修正、数据重配或补充评测任务，并更新下一轮迭代目标与方案。该回路体现的是领域用户的决策价值：平台负责呈现证据和承接任务，用户决定下一轮要改善什么。

### 4.2 DAgger 模型纠正闭环

DAgger 回路针对模型已经暴露出的执行偏差：**指定 Checkpoint 执行 → 发现失败 → 人工接管纠正 → 保存来源与失败信息 → 质检和标注 → 组配新数据集 → 训练新 Checkpoint**。与普通示教相比，该数据直接来自当前模型的薄弱行为，能够把采集资源集中到已有评测证据支持的问题上。

### 4.3 版本与血缘

平台记录业务目标、源数据、标注结果、数据集版本、训练任务、训练配置、Checkpoint、部署记录、评测任务、评测结果和 Badcase 之间的关系。用户可以沿两个方向查询：从评测结果向后追溯使用的模型、配置和数据；从源数据向前查看它进入了哪些数据集、训练任务和模型版本。

这种血缘关系使团队能够区分一次效果变化究竟来自数据新增、数据配比、训练参数、模型版本、部署环境还是评测集变化，也使 DAgger 纠正数据能够明确关联到触发它的 Checkpoint。

## 5. 迭代效果与平台价值

本次验证的端到端迭代周期为 **1 周**，用户体验评分为 **4.32 / 5 分**。这两项指标分别说明流程效率和使用门槛：平台将目标、数据、训练和评测串接后，领域用户可以在一个连续流程中推进迭代；模板、推荐配置、任务状态和版本记录减少了跨工具切换与重复沟通。

平台的效果不只体现在训练结果，还体现在问题解决速度和过程质量上：

- **更快发现和处理问题。**评测结果按总体、分组和单案例展开，用户可以从结果直接定位薄弱场景，减少人工整理失败案例的时间。
- **更有针对性地生产数据。**DAgger 将数据采集聚焦于指定 Checkpoint 的失败行为，避免每轮无差别扩大数据量。
- **更稳定地复用训练输入。**数据集版本与数据快照固定样本范围，降低数据漂移和重复实验造成的比较误差。
- **更低的训练操作门槛。**推荐配置、训练前检查和统一资源管理，使非算法用户能够在受控范围内发起微调。
- **更完整地解释效果变化。**从源数据到 Checkpoint、部署记录和评测结果的血缘关系，支持定位变化来源并复盘迭代决策。

综合来看，**81.2% 的标准场景任务成功率、93.8% 的动作完成率、1 周的端到端迭代周期和 4.32 分的用户体验评分**，共同反映了 Quanta 的两类能力：一方面，平台能够承载真实的采集、训练和评测闭环；另一方面，它将算法和工程团队的专业能力封装为领域用户可理解、可操作、可追溯的工作流。后续迭代应继续按场景和 Badcase 分析成功率与动作完成率之间的差异，并通过 DAgger 和定向数据任务提升端到端任务成功率。
