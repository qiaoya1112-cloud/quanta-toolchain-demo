# 评测用例导入功能设计

方案稿 V1.0 · 2026-10-20

设计依据：[评测组线下测试用例表](https://nwd4iy9rd2s.feishu.cn/base/OQ2UbV65natigrstPbXcwhWinyb?table=tblnjRJV5JV5vLQr&view=vewi0Okt9f)的全部 18 个表头字段（包括隐藏的「前置用例」），以及关联的场景库目录表、Skill 标签维护表、Factor 配置表、Factor 取值说明的字段结构。数据仅作格式样例，不将本次数据质量问题作为功能范围。

本方案覆盖导入模板、字段校验、主数据关联和新增、场景生成、图片处理及导入结果。以下为建议产品行为，尚未实现导入功能或向线上写入数据。

## 1. 整体方案

评测用例列表增加二级按钮「导入」，与「新增评测用例」并列。复用现有抽屉、表单、提示条、表格、标签和分页组件，流程为：

**下载模板 / 上传线下表 → 字段映射与校验 → 关联处理 → 预览并确认 → 查看结果。**

提供两种文件格式：

- **标准模板**：平台日常批量新增使用，按平台字段设计；多值 Factor 和图片用子表填写。
- **线下表兼容导入**：识别本次飞书表头，自动建立映射；无法确认的关联由用户补全。无需先把原表所有列手工改名。

首期采用“新增用例”，已有 ID 默认报错，也可显式选择“跳过已有”；不覆盖已存在记录。新用例建议为未发布、停用，审核发布后再加入评测集。发布状态、启用状态、创建/更新信息由平台生成，不从线下表推断。

## 2. 线下表头与平台字段映射

| 线下字段 | 平台目标 | 处理方式 |
| --- | --- | --- |
| 用例ID | 用例配置 → 用例 ID | 保留原值，作为用例业务唯一标识；内部数据库 ID 另行生成 |
| Stage | 用例配置 → Stage | 名称/匹配键解析为 Stage 定义 ID |
| Story | 用例配置 → Story | 名称/匹配键解析为 Story 定义 ID；与 Stage 的组合由场景库承载 |
| Prompt | 用例配置 → prompt_EN | 英文提示词，必填 |
| prompt_ch | 用例配置 → prompt_CN | 中文提示词，必填 |
| Skill标签 | 用例配置 → Skill | 多选，逐项解析为 Skill 定义 ID |
| Factor | 用例配置 → Factor 配置中的 Factor | 单个配置行单选；一个用例可包含多个 Factor 配置行 |
| Factor取值 | 用例配置 → 对应 Factor 的取值 | 多选，必须保留 Factor 与取值的对应关系；兼容源表 JSON，标准模板不要求用户写 JSON |
| 数据归属 | 用例属性 → 数据归属 | Train→Train-训练，Eval→Eval-白盒，Test-黑盒保持；其他值关联已维护选项或显式新增 |
| 道具 | 场景说明 → 道具 | 保留文本，不创建道具字典 |
| 布置图片 | 场景说明 → 场景示意图/布置图片 | 迁移附件文件；补充平台要求的图片类型，最多 3 张 |
| 来源 | 来源扩展信息 → 来源 | 保留原值，不等同于所属项目或标签 |
| 版本 | 来源扩展信息 → 来源版本 | 保留原值，不映射为优先级、发布状态或评测集版本 |
| story(英文版） | 来源扩展信息 → Story 英文名 | 保留原值，不覆盖 Story 定义名称，也不另建一条英文 Story |
| ft采集组（仅限来源为ft采集场景的数据） | 来源扩展信息 → FT 采集组 | 保留原值，不映射为数据平台用户组或可见用户组 |
| 是否采集过遥操数据 | 来源扩展信息 → 遥操采集标记 | 保留是/否/空；异常内容保留原值并提示，不映射为启用状态 |
| 是否在eval场景集 | 来源扩展信息 → 原 eval 场景集标记 | 保留是/否/空；不能仅凭此字段创建评测集或评测集成员 |
| 前置用例（隐藏字段） | 来源扩展信息 → 原前置用例 | 保留原值，当前平台不恢复前置用例表单或依赖关系 |

平台需要补充而源表没有的字段：

| 平台字段 | 导入如何提供 |
| --- | --- |
| 所属项目 | 导入抽屉必选，默认页面标题旁当前项目；一批一个项目。标准模板行内可填写，但必须与本批一致 |
| 标签 | 可选，标准模板多选；兼容导入可批量指定或保持空，不把“来源”等字段自动转标签 |
| 可见性 | 默认公开，支持整批设置；标准模板可逐行覆盖 |
| 可见用户组 | 可见性为受限时必填；取数据平台用户组，可批量设置或逐行覆盖 |
| 图片类型 | 每张图片选择初始状态 / 目标状态 / 关键物体位置；不能从文件顺序推断 |
| 发布状态、启用状态 | 系统统一生成，不提供导入列 |
| 创建人、创建时间、更新人、更新时间、更新记录 | 平台按真实操作者与时间生成，不伪造线下历史 |

“来源扩展信息”为建议新增的后端结构，用于避免历史字段丢失；可在导入报告追溯，首期不增加普通列表列或占用备注/标签。完整原行、来源文件及行号随导入批次保存。映射页不得静默丢弃任何额外列：需要选择映射至来源信息，或明确忽略。

## 3. 提供给用户的导入模板

### 3.1 Excel 结构

| Sheet | 粒度与字段 | 是否导入 |
| --- | --- | --- |
| 评测用例 | 一行一个用例：用例 ID、Stage、Story、prompt_EN、prompt_CN、Skill、数据归属、所属项目、标签、道具、可见性、可见用户组 | 是，必需 |
| Factor配置 | 一行一个取值：用例 ID、Factor、Factor 取值 | 是，可空 |
| 图片 | 一行一张：用例 ID、文件路径、图片类型 | 是，可空 |
| 填写说明 | 每个字段的必填性、格式、默认值和校验规则 | 否 |
| 选项字典 | 当前项目可见的选项、稳定匹配键与展示名，下载时生成 | 否 |
| 填写示例 | 主表和子表对应关系的少量虚构样例 | 否，不计入待导入数据 |

前三个 Sheet 第 1 行为表头，第 2 行起填写；空白子表不影响导入。按表头识别，列顺序可调整，不按固定列位置搬数据。必填列在模板中用色和填写说明标明，机器字段名不带星号。

Skill、标签、可见用户组采用 **单元格内换行，每行一个完整名称/匹配键**，不按逗号、顿号、斜杠拆分。Excel 原生下拉不承担多选交互，不加宏。固定单选提供下拉；其余在系统预检时匹配。

动态字典建议提供 `展示名〔稳定ID〕` 形式的匹配键。仅填名称时必须唯一匹配；重名需要匹配键。字典页只供选择，不接受用户通过修改字典页直接新增主数据。附件模板为格式草案，动态字典以说明行占位；正式产品应由平台实时生成，不能把线下选项直接当作平台已存在项。

### 3.2 多个 Factor 的填写样例

主表仅一行 `CASE_DEMO_001`，Factor 子表：

| 用例 ID | Factor | Factor 取值 |
| --- | --- | --- |
| CASE_DEMO_001 | 被操作物品属性-尺寸 | 大 |
| CASE_DEMO_001 | 被操作物品属性-尺寸 | 小 |
| CASE_DEMO_001 | 被操作物品属性-几何形态-物体形状 | 球体/圆弧类 |

结果为 **1 个用例、2 个 Factor 配置、3 个取值选择**。同一 Factor 的多行聚合成一个配置，其取值多选；`球体/圆弧类` 保持一个完整取值。不能因子表多行重复创建用例。

## 4. 每个字段的校验逻辑

“必填/非必填”沿用平台当前表单。下表字符上限为建议的统一后端约束，实施时需同步新增/编辑表单；不是现有原型已经具备的全部限制。

### 4.1 评测用例主表

| 字段 | 必填/默认 | 校验与异常处理 |
| --- | --- | --- |
| 用例 ID | 必填 | 文本，去两端空白，建议 1–64 字符；`^[-A-Za-z0-9_]+$`。保留大小写、前导零、横线/下划线。沿用当前全平台唯一规则；文件内重复全部标错，不能自动后行覆盖前行 |
| Stage | 必填，单选 | 唯一解析至 Stage ID；标准引用已发布且启用项。未知/重名进入关联处理，不按相似名称直接匹配 |
| Story | 必填，单选 | 独立解析至 Story ID，不因 Stage 未匹配而禁用。Stage×Story 暂无场景组合不报字段错误，后续预览补齐组合 |
| prompt_EN | 必填 | 去两端空白，建议 1–4,000 字符；保留正文格式。疑似非英文可警告，缺失不可用默认值替代 |
| prompt_CN | 必填 | 去两端空白，建议 1–4,000 字符；疑似非中文可警告。不会默默翻译补齐 |
| Skill | 非必填，多选 | 每行一个完整匹配键；重复项去重并提示，全部解析到 Skill ID。无选项可保留空集合 |
| 数据归属 | 必填 | 匹配标准项或已有自定义项；兼容入口提供 Train/Eval 映射。未知值可由有权限用户明确添加，不随文本自动扩充字典 |
| 所属项目 | 行内可空 | 空值继承本批项目；非空必须与本批一致，且操作者有写权限。项目在抽屉中必选，不允许整批无项目 |
| 标签 | 非必填，多选 | 完整路径或稳定 ID；逐级校验父子关系、使用权限。未知标签前往标签管理维护，不能仅按叶子名称关联 |
| 道具 | 非必填 | 文本，建议≤2,000 字符。含“同上”等引用式内容时要求补齐、明确复制来源或确认置空，不按行顺序猜内容 |
| 可见性 | 默认公开 | 仅公开/受限；兼容导入在抽屉明确整批选择 |
| 可见用户组 | 受限时必填，多选 | 必须是数据平台存在且操作者有权分配的组；未知组不自动创建。公开时如残留组需明确清空，不悄悄改变权限含义 |

Stage/Story/Skill/Factor 名称的语义合并必须确认。匹配优先顺序为稳定 ID → 精确规范名 → 已确认别名；只自动处理两端空白及换行编码，不自动替换括号、拆层级或合并不同中英名称。

### 4.2 Factor 子表

| 字段 | 必填 | 校验与异常处理 |
| --- | --- | --- |
| 用例 ID | 非空行必填 | 必须在本批主表出现，不直接修改批次外已有用例。主表跳过/排除后，所有子行同步跳过/排除 |
| Factor | 必填，单选 | 完整层级名或稳定匹配键；唯一解析至 Factor ID。一级、二级必需，三级可空，不按最末级名称猜测 |
| Factor 取值 | 必填，单值 | 必须属于该 Factor 的取值说明明细；建议≤500 字符。不拆分合法复合文本，不自动填 default |

同一用例同一 Factor 多行合并取值；相同“用例+Factor+取值”重复行去重并警告。完全没有 Factor 子行即表示该用例无 Factor。只有 Factor 没有取值属于错误。

兼容源表时严格解析 Factor 取值 JSON，检测重复键；保留键与值的对应关系。形如 `{"被操作物品属性-尺寸":"大"}` 可直接生成子行；多个 Factor 合并在一个键、多个值挤在换行字符串等情况进入结构化确认，不按位置猜配。Factor 文本列与 JSON 不一致时要求用户选择/修复，不能默默选择一列覆盖另一列。

### 4.3 图片子表

| 字段 | 必填 | 校验与异常处理 |
| --- | --- | --- |
| 用例 ID | 非空行必填 | 同 Factor 子表的父记录规则 |
| 文件路径 | 必填 | 图片包内相对路径，如 `images/CASE_DEMO_001/initial.png`，必须唯一定位实际文件；不支持添加链接 |
| 图片类型 | 必填，单选 | 初始状态 / 目标状态 / 关键物体位置，每张图一个类型；源表无此字段，需要补充 |

无图片允许导入；有图片时 1–3 张，按子表顺序展示，复用现有缩略图。格式沿用 PNG/JPEG/WebP/GIF，校验真实文件可解码；同例重复文件要求确认去重，缺文件/损坏/超 3 张报错。当前组件每张 1MB 限制应在模板说明同步呈现；超限提示压缩或替换，不静默丢图。若未来支持更大原图，需统一附件存储和限制，再更新导入与手工表单。

源飞书附件 token/Excel 图片标记不是平台可直接使用的图片。兼容导入需实际附件文件或有授权的下载通道，存入平台附件存储后建立关系；源图无角色时不能根据顺序猜测。图片包防止路径越界、重名覆盖和解压超限。

### 4.4 来源字段与文件级校验

- 来源、来源版本、Story 英文名、FT 采集组、原前置用例保留原文本；不把历史字段强塞到相近平台字段。采集标记/eval 场景集标记按是/否/空校验，异常原值保留并警告。
- 必需 Sheet/表头缺失、重复表头、模板版本不支持、加密/损坏文件整文件报错。输入仅接收字面值，不执行公式、宏或外部引用；公式单元格要求转为值。
- 全空行忽略；“有内容但无 ID”等不当空行忽略。未知列要求明确映射或忽略。错误报告按文本导出原值，避免公式注入。
- 建议首期限 1,000 个用例/批、Excel≤20MB，子表及图片包分别限额并可配置。额度是建议值，开发前做容量验证。
- 提交时再次校验当前用户对项目、用例、主数据和可见用户组的权限，不能只信任模板字典或预检结果。

## 5. 除评测用例外，其他表的关联写入

### 5.1 关联处理方式

对于 Stage、Story、Skill、Factor、Factor 取值、数据归属：

1. **唯一匹配**：复用已有 ID，不修改定义内容、状态、项目、标签。
2. **名称相似/同名多条**：用户选择已有项，保存本批映射，同一原值一次处理即可影响所有相关用例。
3. **不存在**：用户可“补全并新增”或排除相关用例；新增表单复用现有要素表单，需要相应权限。确认导入前不写正式表。

一个未知要素被多个用例引用，只生成一条候选与一条正式定义。项目、用户组、标签不走导入自动新增，使用右对齐「前往查看或创建」文字链，返回后刷新字典。

### 5.2 各实体写入规则

| 逻辑实体 | 导入写入规则 | 关键约束 |
| --- | --- | --- |
| 评测用例 | 写入 ID、双语 Prompt、属性、可见性等，关联要素均使用 ID | 首期仅新增；建议统一未发布、停用 |
| Stage 定义 | 未知项确认后新增：Stage 场域、所属项目、标签 | 自动内部 ID/独立展示编号；建议未发布、停用 |
| Story 定义 | 未知项确认后新增：Story 任务、所属项目、标签 | 不把 Story 绑定为只能用于一个 Stage；组合写场景表 |
| Skill 定义 | 新增需中文、英文、类别；动作描述、备注可空 | 类别取现有字典，可明确添加；不根据 Prompt 猜英文或类别 |
| Factor 定义 | 新增需一级、二级，三级可空；补取值明细，default 如有须属于明细 | 不从自由文本推测层级，不覆盖已有默认值 |
| Factor 取值说明 | 按 Factor ID+完整取值复用；未知值明确确认后追加说明/举例 | 既有 Factor 增值需主数据编辑权限，记录实际变更，保留原值与 default |
| Skill 类别、数据归属字典 | 有权限、显式选择新增时写入，否则仅关联 | 不自动因拼写差异增加字典项 |
| 场景库定义 | 按已确认用例生成真实五维组合，去重后补齐 | 显式组合实体，不覆盖已有备注、项目、标签 |
| 用例-Skill/Factor/标签/可见用户组关系 | 写入解析后的关联 ID 与 Factor→多取值关系 | 不保留失效外键，不生成孤立子行 |
| 附件与用例附件关系 | 存实际文件并保存用例、角色、顺序 | 文件可按内容哈希复用，关系与权限分别保留 |
| 项目、标签、数据平台用户组 | 只建立合法关联 | 不创建空壳项目/用户组，不从采集组生成权限 |
| 更新记录 | 创建写“通过导入创建”；既有定义变更写字段前后值 | 真实登录人/时间，保留原创建人；无实际变化不编造记录 |
| 导入批次、来源映射与行结果 | 新增批次号、Sheet/行号、原值、映射、结果和错误信息 | 来源有 record_id 时保留，便于追溯与幂等 |
| 评测集、成员、评测任务、评价标准 | 此次导入不写入 | 由后续明确的创建/添加操作维护，不能从来源标记推导 |

建议导入新增 Stage/Story/Skill/Factor 统一未发布、停用；新用例可作为草稿持有待审核关联，依赖未发布/停用要素时不能发布或进入评测集。当前手工快捷新增 Story 的“已发布、启用”是已有特例，本方案建议不直接套用于批量导入，开发前需业务确认。编辑表单要能回显已关联的草稿要素，不能因当前下拉只取启用项而丢失关联。

线下关联表可作为**补全定义的参考字典**，不要求用户日常导入时同步维护四张表。若只有用例文件，未知定义在关联处理表单补全；若迁移时同时提供相关字典，则按以下字段预填并确认，不整表自动创建：

| 线下关联表与字段 | 平台字段/用途 |
| --- | --- |
| 场景库目录表：1级-场域-Stage、2级-任务-Story、3级-原子能力-Skill、4级-factor、factor取值 | 分别对应 Stage、Story、Skill、Factor、Factor 取值；缺失链接不能由取值文本反推。仅作匹配和组合预览依据 |
| 场景库目录表：备注 | 如明确迁移某个完整组合，可预填该组合备注；不覆盖已有备注 |
| 场景库目录表：父记录、文本 3 | 来源结构信息，不生成业务列；有内容则保留原始快照 |
| 场景库目录表：用例id lookup、四个 unique count 计算字段 | 只读派生数据，不导入；用例关联与统计由平台重新计算 |
| Skill 标签维护表：Skill_中文、Skill_EN、可能的动作描述、SKill类别、备注 | 对应 Skill_中文、Skill_EN、可能的动作描述、类别、备注；类别名称差异通过明确映射处理 |
| Skill 标签维护表：Skill | 匹配用的展示名/别名，不另建一个独立 Skill 字段 |
| Skill 标签维护表：工具使用、Key Factor | 当前要素表单没有同义字段，保留来源信息；不自动转成工具外键或 Factor 关系 |
| Factor 配置表：一级、二级、三级、default 标准值 | 对应层级与默认值；Factor 展示名用于核对/匹配 |
| Factor 配置表：取值范围、取值说明关联 | 范围文本用于核对；平台范围由确认后的明细生成，不按斜杠自动拆分。关联优先按有效链接解析 |
| Factor 配置表：场景库目录表关联、父记录 | 用作来源追溯；场景按本批真实组合重建，不复制未知外键 |
| Factor 取值说明：Factor 关联、factor 文本 | 解析到平台 Factor ID；二者不一致需确认，不自动信任其一 |
| Factor 取值说明：取值、说明、举例 | 对应平台取值明细三个字段；按 Factor ID+完整取值关联 |
| Factor 取值说明：字段 2 至字段 16 | 无已定义的平台业务含义；若有内容，要求明确映射或保留来源信息，不能任意丢弃 |

### 5.3 场景库组合如何生成

以**单个用例**为边界：

`Stage × Story × 该用例的 Skill 集合 × 该用例每个 Factor 已选取值`

例如 Skill=S1/S2，F1 选 A/B、F2 选 C，则形成 6 条组合：2×(2+1)。不同 Factor 的取值不相乘；不同用例之间不交叉拼接。取值文本不拆分。

- Skill 为空：使用 NULL Skill 占位，不创建“无 Skill”定义。
- Factor 为空：Factor/取值均 NULL；二者都为空时保留一条 Stage×Story 占位组合。
- 只生成本批用例实际选择的取值，不把 Factor 全部取值范围写进去，也不整体迁移线下场景库。
- 去重沿用当前 `(Stage ID, Story ID, Skill ID, Factor ID, Factor取值)` 五维规则，空值统一表示；命中组合但所属项目冲突时阻断并人工处理，不能覆盖原项目。
- 不向 Story 的 Skill/Factor 关联数组整体追加再做笛卡尔积；应使用独立场景组合实体，避免生成虚假场景。
- 场景用例数按真实关联查询，包含全部发布/启用状态，同一用例同一取值仅计一次，不手动累加。

若未来要求场景按项目隔离，需要同时调整全平台唯一键及既有数据，不能仅在导入中加一套项目去重规则。当前原型批量新增场景要求 Skill/Factor 非空，导入需适配用例允许空关联的规则，不能直接套现有批量场景表单。

## 6. 抽屉步骤与错误反馈

| 步骤 | 页面内容 | 进入下一步条件 |
| --- | --- | --- |
| 上传 | 项目、格式、已有 ID 处理方式；下载模板、上传 Excel/图片包；兼容导入增加整批可见性等补充配置 | 文件结构可读取，必需配置齐全 |
| 字段映射 | 展示“源表头→平台字段”；本次线下表使用默认映射，保留来源扩展信息 | 所有输入列有明确去向或明确忽略 |
| 校验与关联 | Tab：用例校验、关联要素、场景组合、图片；顶部可导入/待处理/跳过数量 | 错误为 0，待确认项处理完 |
| 确认 | 用例数、各表新增/复用数、图片数、所属项目、默认状态、警告清单 | 至少一个新增用例，用户确认 |
| 结果 | 批次号、成功/跳过/空行数、各表新增数；查看本批用例、下载报告 | 成功持久化或明确失败 |

错误区分：**错误**阻止提交；**待确认**需映射/补全/选择；**警告**允许确认后继续。表格定位到 Sheet、原行号、用例 ID、字段、原值、原因、建议，下载错误文件保留原模板结构并附错误明细，便于修正重传。

可选择“排除有误用例”，同时排除其子行及仅被它引用的新增候选，再生成预览。首期不隐式导入一半。预检、映射、取消都不写正式主数据；新增定义也暂存到最终提交。

## 7. 写入一致性、幂等和后续扩展

确认后的写入顺序：

1. 暂存文件、原值、映射与校验版本，生成批次 ID；图片先准备到受控附件区。
2. 提交时重新检查权限、记录版本、关联状态、业务 ID/主数据/场景唯一键，数据变化则要求重新预检。
3. 在一个数据库事务内写新增定义与取值 → 场景组合 → 用例及关联/附件关系 → 更新记录、来源信息和批次结果。
4. 全部成功提交，失败整批回滚；未被成功记录引用的暂存附件清理，不删除复用对象。

幂等使用批次 ID+预览版本；双击、断网重试返回同一结果。相同文件哈希可提示历史批次，但不能单独决定跳过，因为用户可能调整了项目或映射。唯一性必须有后端约束；同一候选并发新建要再次匹配，不能只靠“先查后写”。

当前原型使用本地数组/localStorage，正式导入需要后端暂存、事务、附件存储和审计，不能用覆盖整个本地数组模拟可靠导入。对于草稿引用草稿要素、空 Skill/Factor 场景占位、来源扩展信息，也需补齐统一读写支持。

后续若开放“更新已有”：仅未发布且有编辑权限；ID 不可修改，已发布记录不覆盖；空白表示不修改，显式清空采用单独机制；Skill/Factor/标签等整组替换须预览差异；保留创建信息及隐藏字段，只记录实际变化。更新模式与新增模板语义分开，不在首期悄悄支持覆盖。

## 8. 核心验收样例

| 样例 | 预期 |
| --- | --- |
| 最小必填齐全，Skill/Factor/图片都空 | 新增 1 个草稿用例，正确关联项目与 Stage/Story |
| prompt_CN 缺失、文件内重复 ID、已有 ID | 分别报字段错、重复错；显式跳过已有时整例及子行一起跳过 |
| 同一 Factor 两个值，另一个 Factor 一个复合文本取值 | 一个用例、两组 Factor、三个完整取值；不把复合文本拆开 |
| 未知 Story 被多个用例共用 | 一次补全、一条新增 Story，多个用例复用，正确生成各自真实场景 |
| 已有 Factor 新增取值 | 明确权限与确认，只追加新值，默认值与原取值保留 |
| 受限但未选组、未知组、跨项目无权引用 | 阻止提交，不自动变公开或创建用户组 |
| 图片缺失/超限/未指定类型 | 定位具体用例和文件，要求补齐、替换或明确不导图片 |
| “是否在eval场景集”为是，或 FT 采集组有内容 | 只保留来源信息，不生成评测集、成员或用户组 |
| 中途失败、重复提交、预检后被他人修改 | 整批回滚、幂等返回、冲突重检，无孤立记录 |

正式模板下载时应完整分页读取当前可见字典；本方案不要求把线下全部选项值直接搬入平台。少量填写示例只解释格式，不作为可直接创建主数据的依据。
