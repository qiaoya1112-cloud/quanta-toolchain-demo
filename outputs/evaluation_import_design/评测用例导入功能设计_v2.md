# 评测用例批量导入功能设计 V2

日期：2026-10-27。状态：设计基线；本地原型已实现核心流程。下述正式权限、保留周期仍为接入规范，不代表 Demo 已有完整账号/权限体系。

本稿以当前项目代码 `eval_case_import.py`、`static/eval_catalog/catalog.js`、`templates/eval_catalog/page.html` 及本次用户要求为依据。模板字段以仓库现有 18 列模板定义为基线；本次没有重新访问飞书，不声明线上模板版本已重新核对。本文替代 V1.1 中的图片包、人工映射/二次确认、部分导入、新要素默认草稿等旧建议；旧稿和旧模板文件保留供追溯，不能作为本稿的最新模板。

## 1. 产品结论

1. 流程为：打开「批量导入」抽屉 → 选择重复 ID 处理方式 → 上传一个文件 → 点击「校验并导入」→ 服务端全量校验 → 全部通过自动整批写入。没有预览确认或逐条确认步骤。选中文件只进行格式/大小检查，不立即覆盖已有数据；按钮的一次提交就是导入授权。
2. 任一阻断错误，整批评测用例及关联数据均不写入。允许的结果是「全部符合策略后导入」或「全部不写入」，不存在部分成功。跳过已有 ID 是明确的处理策略，不是失败行被部分导入。
3. Stage、Story、Skill、Factor、Factor 取值，先查要素定义，再查场景组合。存在且可用则复用；不存在且资料完整则自动创建；存在但未发布/停用则报错，不自动发布、启用，也不另建同名记录绕过状态。
4. 新用例为「未发布、未启用」；本次自动创建的 Stage/Story/Skill/Factor 为「已发布、启用」，所属项目来自用例，创建人与更新人为实际登录用户。自动创建需要相应创建、发布和启用权限。
5. 增加「导入记录」，直接放在导入抽屉下半部分，不分 Tab、不提供详情。任务、结果和下载文件由服务端保存，退出页面后继续执行；用户再次打开可查询历史。同租户内也按真实用户 ID 严格隔离。

## 2. 抽屉与结果交互

沿用数据平台「指令管理 → 上传指令表」及现有共享抽屉、Tab、上传框、选择器、表格、状态标签、文字链按钮和分页。不新增一套视觉样式，不另加一级菜单。

### 2.1 本次导入

- 标题「批量导入评测用例」，右侧文字链「下载模板」。
- 上传区域下方直接展示导入记录：文件（点击下载）、提交时间、状态（成功/校验中/导入中/失败）。
- 表单：「用例 ID 重复时」单选「跳过（默认）/ 更新」；一个文件上传区域，支持点击或拖拽。
- 上传说明：`支持 XLSX、CSV，单个文件不超过 12 MB，最多 5000 条；图片请直接插入 Excel。`
- 选择更新时辅助文字：`按文件中提供的字段更新；非必填字段留空会清空或恢复默认，未提供的列保持原值。`
- 底部主按钮「校验并导入」，文件未就绪时禁用。提交后策略与文件锁定；需要换文件则创建新任务。
- 处理中只展示当前阶段与已处理行数，不编造百分比。服务端确认接收完整文件后允许关闭抽屉；上传途中关闭提示「上传尚未完成，关闭将取消本次上传」。
- 同一批次只能提交一次；连续点击、刷新或网络重试返回同一任务。

### 2.2 状态和反馈

| 状态 | 界面文案/行为 | 业务数据写入 |
| --- | --- | --- |
| 待上传/已选择文件 | 选择文件，点击「校验并导入」 | 无 |
| 上传中 | 正在上传文件… | 无；任务记录可先建立 |
| 校验中 | 正在校验，已处理 {n}/{total} 条 | 无；关联新建只建立计划 |
| 导入中 | 校验通过，正在导入… | 在一个事务中处理，提交前不可见 |
| 已完成 | 共 {total} 条；新增 {created}、更新 {updated}、未变更 {unchanged}、跳过 {skipped} 条 | 全部提交；全跳过/未变更也为完成 |
| 校验失败 | 校验未通过，{failedRows} 条记录存在 {errorCount} 项错误，整批未导入。请下载错误文件修正后重新上传。 | 无 |
| 上传失败 | 文件上传失败，请重新上传。 | 无 |
| 导入失败 | 导入失败，整批数据未写入。可重新发起导入。 | 已确认事务回滚才使用该状态 |
| 状态确认中 | 正在确认导入结果，请稍后查看记录。 | 网络中断/提交结果不确定，不宣称未写入 |

校验失败自动尝试下载错误文件，同时保留「下载错误文件」入口；浏览器阻止自动下载不影响任务。错误文件生成失败时显示「错误文件暂未生成，请重试」，支持重新生成，不重新执行导入。文件级错误无法计算错误行数时显示具体错误，不显示虚假的「0 条错误」。

### 3.2 自动新建所需的资料补充

现有 18 列缺少新 Skill 的必填类别，Factor 也不能只凭一个末级名称推断层级。建议做以下最小扩展，保持一行一个用例，不要求用户维护独立要素子表：

| 调整 | 填写规则 | 原因 |
| --- | --- | --- |
| 增加可选列「Skill 类别」 | 按 Skill 的逐行顺序一一对应；例如 Skill 两行、类别两行。全部命中现有 Skill 时整列可空；混合新旧 Skill 时类别逐项填写，既有项须与现有类别一致 | 新 Skill 类别必填，不能无依据全部归为动作类；类别取现有类别选项 |
| Factor N 约定完整层级 | 新 Factor 使用「一级 > 二级」或「一级 > 二级 > 三级」；一级、二级必填，三级可不填；已有完整显示名或 ID 继续可用 | 缺少层级时无法正确创建 Factor |
| 可选扩展「标签」 | 使用标签完整路径或唯一 ID，多项换行；取现有标签，不自动创建 | 对齐用例属性，不擅自把它描述为当前模板已有列 |
| 可选扩展「图片类型」 | 按同一单元格内图片从上到下、从左到右的顺序逐行填写初始状态/目标状态/关键物体位置；有填写时须与图片数量相同；无类型列或整格空统一默认初始状态 | 当前图片列没有类型信息；不按图像内容猜测 |

发布新模板时默认增加 Skill 类别列；标签、图片类型可一并列入新版，但旧 18 列模板仍可导入：不涉及新 Skill 则不受影响，涉及新 Skill 且缺类别按明示规则报错。不要在不更新模板说明的情况下新增隐含必填项。

Factor 取值的「说明、举例」目前非必填，新取值可先为空；新 Factor 的 default 标准值允许为空，不擅自选择第一个值。后续在要素定义补充。既有说明、举例、default 均保留。若未来这些字段变成必填，必须同步升级模板和表单校验。

### 3.3 多值、文本与长度

- 新模板统一：Skill、Factor 取值、可见用户组、标签使用单元格内换行，每行一个完整选项。单选 Stage/Story/Factor 不接受多行名称。
- 已有值首先整格精确匹配。`球体，圆弧类`、`球体/圆弧类` 都可能是一个完整取值，不能见逗号或斜杠就拆分。
- 兼容旧模板逗号/分号分隔时，仅在所有片段均能唯一匹配已有选项时解析；涉及新建或存在歧义时提示改为换行。新建包含分隔符的单个取值可在单元格外层加双引号，解析时只去掉这对明确的引用符；填写说明给出样例。CSV 的文件级引号与该单元格文本规则分别解析。
- 同单元格重复的 Skill/取值/用户组/标签去重并记录非阻断提示；不同 Factor 配置列重复选择同一个 Factor 则报错。
- 名称和关联键只去首尾空格、统一换行与 Unicode NFC；不忽略大小写、不模糊匹配、不自动合并不同名称。兼容已批准的表头别名及中英文括号展示形式，但不得产生多命中。
- prompt、道具保留正文及换行；用 trim 判断是否空，不清除有意义的内文空格。EN/CN 不进行语言比例检测，不因英文缩写、中文专名、代码或标点混用拒绝，也不判断翻译语义是否相同。
- 日期、布尔、Excel 错误值不能被静默转换成 ID/选项；数字型 ID 仅在无损还原为纯整数文本时兼容，超过 Excel 精度或科学计数法导致损失则报错。模板 ID 列设为文本。

以下是**建议新增并需与手工表单、数据库统一的长度约束，不是现行已实现限制**：用例 ID 100 字符；Stage/Story、Skill_CN/EN、Factor 每级名称 200 字符；数据归属/Skill 类别 100 字符；Factor 单个取值 500 字符；prompt_EN/CN 各 10,000 字符；道具 2,000 字符。源模板中较短的推荐长度不直接作为拒绝标准。实现时长度以 Unicode 字符计数，模板和服务端使用同一配置，超限不截断。

## 4. 关联复用与自动新建

### 4.1 先区分两层

「要素定义」保存 Stage/Story/Skill/Factor 及 Factor 取值；「场景库定义」保存它们的组合。组合没有出现过，不表示要素不存在。匹配顺序：

1. 只在当前用例所属项目内匹配 Stage/Story/Skill/Factor；稳定 ID 精确匹配优先，其次完整名称/层级。不跨项目复用。
2. Stage/Story/Skill/Factor 均按项目内唯一，允许不同项目存在同名要素，分别保存独立内部 ID；既有要素的项目不因导入而改写。
3. 明确填写内部 ID 却查不到时按失效引用报错，不能把 ID 字符串当作新名称；用户可以改填完整名称以新建。
4. 命中唯一记录后，分别检查已发布与启用状态；两项不满足时合并报告。不因为当前项目记录停用而改选其他项目同名记录。
5. 查不到名称且无冲突，校验新建资料与权限，登记待创建记录；同批相同定义只创建一次。同名新候选分属不同项目时分别新建，不产生全局唯一性冲突。
6. 全部行通过之后，再将上述计划与用例在同一事务提交。

### 4.2 各实体写入规则

| 实体 | 已有且可用 | 不存在 | 不可用/冲突 |
| --- | --- | --- | --- |
| Stage | 复用 ID，不改名称、项目、标签 | 名称合法且有权限则新建；已发布、启用 | 未发布、停用、重名、无权限均阻断 |
| Story | 复用 ID；无需预先与 Stage 组合 | 新建独立 Story；与本行 Stage 的关联落到场景组合 | 不修改旧 Story 的隐藏 Stage/Skill/Factor 关联数组，不因 Stage 不同复制 Story |
| Skill | 完整中英文名/ID 匹配；有补充类别时核对一致 | 中文、英文、类别齐全才新建；其余非必填字段空 | 中文或英文与已有记录局部冲突而无法唯一识别，报错，避免中英文错配 |
| Factor | 完整层级/ID 匹配，不改原层级和默认值 | 解析新层级，合并本批该 Factor 的去重取值；至少一个有效值后新建 | 层级缺失/歧义、重名、状态异常均阻断 |
| Factor 取值 | 按 Factor ID + 完整取值文本复用 | 在该 Factor 下追加取值，说明/举例为空；有明细 ID 则系统生成 | 不以其他 Factor 下的同名值替代；父 Factor 不可用则阻断 |
| 场景库定义 | 五维组合命中则复用；保持原项目、备注、标签 | 只创建本行实际选中的组合；沿用用例项目 | 命中但无使用权限等按关联规则阻断，不能复制绕过 |
| 数据归属选项 | 标准别名归一化后复用 | 沿用表单支持新增选项的行为；有选项维护权限时新建一次 | 非法值、过长、无新增权限阻断；不能默认改成 Eval |
| 所属项目、用户组、标签、Skill 类别 | 只关联有效且有权使用的既有记录 | 报错，前往相应管理页维护 | 本导入不自动创建这些表 |
| 用例关系、附件关系 | 更新按明确的字段替换规则处理 | 写入用例–Skill、用例–Factor–取值、可见用户组、标签、附件关系 | 不留下悬空外键 |

**Factor 取值当前没有独立发布/启用状态**，因此复用值时检查其所属 Factor 的状态，不虚构一个取值级状态字段。将来若平台正式增加取值状态，则增加同样的状态检查及错误文案。场景库定义当前不展示发布/启用状态，也不把隐藏的旧状态字段作为新的拒绝条件。

为已发布 Factor 追加新值属于此次明确授权的定义修改，需要编辑权限及审计；新旧取值的说明、举例和默认值不覆盖，不删除未被本批选中的值。审计写明「由导入任务 {jobId} 新增取值：…」。新要素创建、自动发布/启用也分别留下真实审计事件。

### 4.3 场景组合

唯一键沿用 `(Stage ID, Story ID, Skill ID, Factor ID, Factor取值)`，包含租户隔离，空值统一表示，不在导入里私自加入项目维度。

每条用例的组合数量为：`max(1, Skill 数量) × max(1, 各 Factor 所选取值数量之和)`。Stage/Story 每行各一项。Skill 空则用空占位；Factor 配置空则 Factor/取值均为空占位。例：2 个 Skill，F1 选 A/B，F2 选 C，生成 6 个组合，不是 2×2×1，也不与其他用例跨行交叉。

仅生成实际引用的组合；已有和同批组合去重。用例更新后只补充所需的新组合，不顺带删除可能被其他数据引用的旧场景。各项目使用独立的要素 ID 生成场景组合，不跨项目复用或覆盖。

## 5. 重复 ID：更新 / 跳过

| 情况 | 跳过（默认） | 更新 |
| --- | --- | --- |
| ID 不存在 | 新建用例 | 新建用例 |
| ID 已存在且有权访问/操作 | 本行跳过，既有用例与关联数据均不变 | 更新该用例及提供的关系字段 |
| ID 在本文件内重复 | 所有重复行报错 | 所有重复行报错；不采用最后一行覆盖 |
| ID 命中无权使用的记录 | 使用统一不可用文案阻断，不泄露详情 | 同左 |
| ID 相同但内容完全未变 | 跳过 | 计为「未变更」，不改更新时间、不新增字段修改日志 |

用例 ID 沿用现有平台的大小写敏感唯一性；不得按导入用户或项目缩小重复检查范围。用户隔离的是导入任务历史，不是把同一个用例 ID 变成每个用户可各自创建一份。

跳过行仍执行文件级结构检查、ID 格式检查、文件内重复 ID 检查、授权检查；除此以外不校验它不会使用的业务字段、不创建其关联数据。错误报告中跳过行错误原因留空，任务详情记录该行的跳过原因。

更新时：

- 用例 ID 不变；必填业务字段必须提供并覆盖。非必填列不存在则保留原字段；列存在但为空，则清空，或按字段明确默认值处理。
- 数据归属列空恢复 Eval-白盒；可见性列空恢复公开。公开时旧用户组清空；若文件仍填了用户组则报错。受限时使用更新合并后的用户组校验，不能漏检保留的旧组。
- Skill/标签/用户组/图片为整组替换；Factor 列任一组存在时，所有提供的 Factor 组作为新的完整配置，不能只覆盖编号 1 而保留未提供的旧编号。
- 保留既有发布/启用状态、创建人、创建时间、内部 ID、隐藏字段和不在导入范围内的关联。按平台已有可编辑规则更新，不额外引入「只有未发布才能更新」的限制。被锁定/无编辑权限则报错。
- 对合并后的最终用例执行全部状态和外键检查，包括文件未提供但保留下来的 Skill/Factor/用户组等，防止更新后仍引用不可用对象。
- 有实际业务变化才更新更新人/时间和更新记录；已有评测集成员不因导入被新增/移除，也不自动发布、启停用例。

## 6. 校验顺序与完整错误清单

以下覆盖本方案支持的字段和流程。`{字段}`、`{值}`、`{行号}` 等为实际值占位符；以字段/列顺序稳定输出，同一问题不重复。文案同时用于抽屉与错误文件，服务端返回稳定错误码。依赖字段缺失时不堆叠派生错误，例如 Factor 无法匹配时不继续报其每个取值不存在。

顺序：文件安全与结构 → 全文件 ID 与重复策略 → 待处理行基础字段 → 字典/状态/权限 → 同批一致性与组合计划 → 写入前再校验 → 原子提交。可继续解析时收集所有独立错误，不只返回第一个。

## 7. 错误文件

1. 文件名：`原文件名_错误明细_任务编号.xlsx`。CSV 也返回 XLSX，避免编码和图片能力差异。
2. 保留原数据表列序、行序、原行号、可读原值和可安全读取的图片；不只导出错误行，方便修完整批重传。新增且仅保留一列「错误原因」，固定在数据表最右侧。已有错误列覆盖重写，不能不断追加。
3. 每个错误行汇总所有独立错误，单元格内换行，例如：

   ```text
   prompt_CN 不能为空。
   Story「收纳物品」已停用，请先启用后再导入。
   可见性为受限时，至少填写一个可见用户组。
   ```

4. 无错误的行「错误原因」为空，但也没有导入。增加「校验说明」Sheet，醒目说明「本批次未导入任何数据；错误原因空白仅表示该行没有发现错误，不表示已导入」。同时记录总数、错误行数、跳过数和文件级错误。
5. 表头/工作表错误放入校验说明页，指明工作表和列/范围，不通过把说明插进数据行导致行号错位。原文件完全不可读时返回「文件名、错误原因」的轻量报告；不能承诺恢复损坏内容。
6. 公式不执行；错误报告中以文本保存公式表达式，防止打开报告时执行不可信公式。图片损坏无法保留时报告明确说明，不把缺失图片伪装成已保留。
7. 用户修正后可以直接重传错误文件，解析器忽略「错误原因」列和「校验说明」Sheet，重跑全部校验，不因残留旧错误文案继续失败。新上传形成新任务，关联原失败任务 ID，不篡改原历史。
8. 下载采用服务端任务产物，不依赖浏览器临时 Blob；关闭抽屉或更换设备后同一用户仍可下载。

## 8. 我的导入记录

### 8.1 有必要做，建议与此次导入一起交付

原因：校验/图片解析可能耗时；用户会关闭页面；错误文件需要反复下载；重复 ID 的更新可能覆盖数据，需要知道是谁、何时、用哪个文件和哪种策略操作。任务记录也是失败重试和幂等的基础，不只是额外报表。

列表位于上传表单下方，默认按提交时间降序，采用现有表格与分页。仅展示三列：

| 文件 | 提交时间 | 状态 |
| --- | --- | --- |
| 文件名文字链，点击下载 | yyyy-MM-dd HH:mm:ss | 成功 / 校验中 / 导入中 / 失败 |

不提供详情、操作列或额外 Tab。失败记录的文件链接下载带「错误原因」的 XLSX；成功/处理中下载原文件。当前任务的简短结果说明在上传区域下方展示。增加「mock 错误数据」按钮，生成错误 CSV 并自动走真实上传、校验、错误报告及历史记录流程；错误数据不会写入用例表。

### 8.2 用户隔离与权限

- 所有任务归属由服务端登录态写入 `(tenant_id, created_by_user_id)`；接口不能接受客户端传来的用户 ID 作为可信归属。显示姓名只用于展示，不作隔离键。现有演示用户 Joanna Qiao 更不能代替认证。
- 列表、详情、轮询、原文件/错误文件/结果文件下载、重试、错误报告重建，都在服务端校验租户和用户一致。仅在前端隐藏别人记录不满足要求。
- 相同用户重新登录、刷新、跨设备能看到自己的记录；不同账号在同一浏览器也不能读缓存里前一账号的文件/任务，切换账号清理用户级缓存。
- 常规入口不提供「全部用户记录」；若以后需要管理员审计，使用独立授权入口和访问审计，不默认突破隔离。
- 错误文件和原文件包含业务原文，下载同时重新检查当前相关项目的数据读取权限。权限已收回时只保留允许展示的任务概况并禁用下载；不能用长效公共 URL 绕过。
- 私有存储，短时下载凭证或认证下载代理；任务号不可枚举不是授权替代。文件路径不由用户直接指定。

### 8.3 保存周期建议

建议任务元数据/结果摘要保留 180 天，原文件、错误文件、逐行明细保留 30 天；这是产品建议，需接入公司统一保留策略，并在下载区域显示具体到期时间。业务实体审计按平台审计策略保留，不随临时文件一起清除。到期后记录仍显示状态和统计，下载置灰并提示到期，不变成失败任务。首期不提供删除历史按钮。

## 9. 服务端一致性与数据模型

### 9.1 建议新增的持久化对象

| 对象 | 核心字段 |
| --- | --- |
| import_job | ID、租户、真实用户 ID、原文件名、存储引用、文件 hash、模板/规则版本、重复策略、状态、阶段、创建/开始/结束时间、统计、父任务 ID、幂等键、文件到期时间 |
| import_row_result | job_id、原 Sheet/行号、用例 ID、行处理结果、错误码/字段/错误文案数组、目标用例 ID/版本 |
| import_artifact | job_id、原文件/错误文件/结果文件类型、私有存储引用、校验和、生成状态、到期时间 |
| 实体审计关联 | job_id、实体类型/ID、操作、变更前后值、真实用户、时间 |

任务记录的用户隔离不改变已有业务实体的项目/可见性权限。

### 9.2 原子提交

1. 建立任务、上传到私有暂存区；文件完整接收后由服务端任务队列执行，前端关闭不取消已提交任务。上传未完成的超时任务标记上传失败并清理残留。
2. 读取一致的业务快照；计算跳过行和全部关联写入计划，记录各引用对象版本。未全通过不写任何业务表。
3. 将新图片准备为不可公开的持久附件；准备失败停止，不能先保存用例再补图片。
4. 事务中再次检查授权、用例/关联版本、唯一键与状态，按依赖写入要素 → 取值 → 场景 → 用例及关系 → 审计。用例最终引用有效对象，不制造半成品。
5. 业务数据、成功计数、任务完成状态或可靠 outbox 完成事件在同一数据库事务中提交；任务失败记录在回滚后单独保存。对象存储不在数据库事务里，使用暂存/提交引用/失败清理方案，不承诺跨存储天然原子。
6. 幂等键按用户和任务生成；客户端重试同一提交复用任务。文件 hash 只用于提示同文件历史，不直接跳过，因为策略、权限和平台数据可能已变化。
7. 服务端重启用租约/持久队列恢复；提交结果不确定时查询持久状态，不能先报失败再重复写。修正文件、变更策略或正式重试创建新的关联任务，旧任务保留。

五维场景唯一键、Factor 取值键、用例 ID 和各要素既有唯一性必须由数据库约束及规范化键保障；不能只依靠预检中的数组查重。并发新增值只追加自己的集合，不以整个 Factor 定义覆盖另一任务追加的取值。

建议 API：创建/提交任务、查询我的任务列表、查询单任务状态/结果、按任务下载产物、重新生成错误文件。所有接口以服务端认证为准。业务错误返回结构化 `code/sheet/row/column/field/message`，前端不自行决定是否通过。

## 11. 核心验收用例

| 场景 | 期望结果 |
| --- | --- |
| 100 行全部有效 | 一次提交 100 行及依赖，成功计数正确 |
| 第 99 行 prompt_CN 空，前 98 行需要新建 Stage | 业务表零写入；第 99 行报告必填错误，不残留前 98 行 Stage |
| 既有 Factor 正常，新取值「大」不存在 | 只追加「大」，保留旧取值/默认值/说明，新增相关场景与用例 |
| Factor 不存在且完整层级/取值齐全 | 同批只建一个 Factor，合并去重取值，已发布启用 |
| Factor 不存在，仅填末级名称 | 返回层级不完整错误，不能猜一级二级 |
| 新 Skill 缺类别 | 错误文件要求补 Skill 类别；不偷偷默认动作类 |
| 既有 Story 未发布且停用 | 返回一条合并状态错误，不自动新建重名 Story |
| Stage/Story 都存在但组合不存在 | 复用要素，只补场景组合 |
| Skill/Factor 都空 | 用例可导入；保留合法空占位场景组合 |
| 同一用例 2 Skill、F1 2 值、F2 1 值 | 生成最多 6 条新的去重组合 |
| 取值是「球体，圆弧类」且已有完整定义 | 复用一个完整值，不拆成两个 |
| 跳过策略，已有 ID 的行其他业务字段有错 | 行跳过且不创建依赖；其他行校验通过即可导入 |
| 跳过策略，同文件两行同 ID | 两行都报重复错误，整批不写入 |
| 更新策略，未提供图片列与 Skill 列 | 保留原图片/Skill，仍校验最终引用可用性 |
| 更新策略，图片列/Skill 列存在但为空 | 清空图片/Skill；有实际变化才写更新日志 |
| 已发布用例正常更新 | 保留发布/启用/创建信息，遵守已有编辑权限与锁定规则 |
| 全跳过/全未变更 | 任务已完成，新增/更新为 0；不制造业务变更日志 |
| 一个字段错误和一张损坏图片 | 收集两种独立错误，报告说明不能保留的损坏图片 |
| 修正错误文件后再次上传 | 忽略旧错误原因/校验说明，创建新任务，全部重新校验 |
| 处理中关闭抽屉再打开 | 我的记录持续显示真实进度；不会重复提交 |
| 校验后依赖被停用 | 提交复验失败，整批回滚，具体行报告状态变化 |
| 两任务并发创建同 ID | 唯一键防止重复；后提交任务重新校验，不悄悄覆盖 |
| 数据已提交但客户端断网 | 重新打开显示原任务已完成，不重复写入 |
| 用户 A 提交；用户 B 获取任务 ID 请求详情/下载/重试 | 服务端拒绝，B 的列表也看不到 A 的任务 |
| 用户 A 换浏览器/设备 | 可查本人历史和未过期且仍有权限的文件 |
| 更新无差异但缺失场景需补充 | 用例计为未变更，关联新增独立计数，留下实际场景创建审计 |
